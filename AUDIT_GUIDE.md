## ⚙️ 2. Чек-лист аудиту архітектури та якості коду

### 2.1. Статична збірка та ізоляція (SSG Isolation)
- [ ] **Конфігурація Astro**: Файл `astro.config.mjs` має містити `output: 'static'`.
- [ ] **Чистота рантайму**: Відсутні важкі серверні залежності Node.js у підсумковому бандлі.
- [ ] **Швидкість збірки**: `ASTRO_TELEMETRY_DISABLED=1 npx astro build` має завершуватися за < 1 секунду без помилок та warning'ів.
- [ ] **Динамічні роути**: Усі 6 кейсів (`/cases/[slug]/`) та сервісні сторінки генеруються статично через `getStaticPaths()`.

### 2.2. Контейнеризація та відтворюваність (Docker)
- [ ] **Multi-stage Dockerfile**: 
  - Етап 1 (Build): `node:18-alpine` збірка static-файлів у `dist/`.
  - Етап 2 (Runtime): `nginx:alpine` з віддачею готової статиків.
- [ ] **Розмір контейнера**: Оптимальний розмір підсумкового образа < 30MB.
- [ ] **Nginx кешування**: У `nginx.conf` налаштовано кешування статичних ресурсів:
  ```nginx
  location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2)$ {
      expires 1y;
      add_header Cache-Control "public, max-age=31536000, immutable";
  }
  ```

## 📊 3. Чек-лист аудиту аналітики та телеметрії

### 3.1. Google Analytics (GTM / `gtag.js`)
- [ ] **Конфігурація згоди (Consent Mode)**:
  ```javascript
  gtag('consent', 'default', {
    'analytics_storage': 'denied'
  });
  ```
  За замовчуванням збереження кукі вимкнено до моменту вибору користувача.
- [ ] **Коректність оновлення згоди**: При натисканні «Прийняти всі» викликається `gtag('consent', 'update', { 'analytics_storage': 'granted' })`.

### 3.2. Amplitude Analytics
- [ ] **Серверна зона ЄС**: Використовується параметр `{ serverZone: 'EU' }`.
- [ ] **Контроль фонових подій (No Event Spam)**: 
  - Автоматичне перемикання слайдів каруселі кажні 5 секунд **НЕ шле** події в Amplitude.
  - Подія `carousel_slide_change` реєструється виключно при ручному натисканні кнопки користувачем (`isManual === true`).

## 🍪 4. Чек-лист аудиту конфіденційності та GDPR

- [ ] **Приховування та збереження**: Після кліку на «Прийняти всі» або закриття банер миттєво отримує `display: none` / `hidden` і стан зберігається у `localStorage.getItem('ai_hub_cookie_consent')`.
- [ ] **Відсутність повторного спаму**: При повторному переході на сайт банер більше не з'являється.

### 4.2. Політика конфіденційності (`/privacy/`)
- [ ] **Безпека публічного тексту**: Відсутні відкриті технічні ідентифікатори та API-ключі.
- [ ] **Юридична повнота**: Присутні всі 9 розділів (Загальні положення, Категорії даних, Cookie, Цілі обробки, Захист, Треті особи, Права користувачів, Зміни, Контакти) відповідно до GDPR та Закону України «Про захист персональних даних».

## 🔍 5. Чек-лист аудиту SEO та індексації

- [ ] **XML Sitemap**: Динамічний роут `/sitemap.xml` відкривається за адресою `https://<domain>/sitemap.xml` та містить усі 11 канонічних URL-адрес з правильною кодуванням UTF-8.
- [ ] **Robots.txt**: Файл `/robots.txt` доступний та вказує точний шлях до `Sitemap: https://<domain>/sitemap.xml`.
- [ ] **Семантична вкладеність HTML5**: На кожній сторінці присутній тільки один тег `<h1>`, заголовки списків вкладені рівно по ієрархії `<h2>` -> `<h3>`.
- [ ] **OpenGraph метатеги**: Сторінки мають теги `og:title`, `og:description`, `og:type="website"`.

## 🧪 7. Інструкція з виконання аудиту (Audit Execution Workflow)

### Крок 1. Перевірка локальної збірки
```bash
# Клонування або перехід у репозиторій
cd ai-hub-webpage

# Перевірка типів та локальної static-збірки
ASTRO_TELEMETRY_DISABLED=1 npx astro build
```

### Крок 2. Перевірка Docker-контейнера
```bash
# Збірка Docker-образа
docker build -t ai-hub-webpage:audit .

# Запуск локально
docker run -p 8080:80 ai-hub-webpage:audit

# Перевірка доступності сторінок
curl -I http://localhost:8080/
curl -I http://localhost:8080/sitemap.xml
curl -I http://localhost:8080/privacy/
```

### Крок 3. Аудит Core Web Vitals (Lighthouse CLI)
```bash
# Запуск автоматизованого тесту продуктивності та доступності
npx lighthouse-ci collect --url=https://ai-hub-webpage-572664673489.europe-west1.run.app/
```
