# AGENTS.md — правила роботи з кодом ITSF AI Hub

> Покласти цей файл у **корінь репозиторію**. Продублювати як `CLAUDE.md` (Claude Code) і `.github/copilot-instructions.md` — різні агенти читають різні імена. Файли мають бути ідентичні; узгодженість перевіряє CI.

---

## 0. Головне правило

**Мінімальний диф.** Змінюй рівно те, про що просили, і нічого більше.

Якщо поруч із задачею ти бачиш код, який здається неоптимальним, неохайним або застарілим — **не чіпай його**. Напиши про це в підсумку окремим списком «Помічено, але не змінено». Рішення про рефакторинг приймає людина.

Це не побажання щодо стилю. Це вимога: попередні неузгоджені правки вже призводили до відкату продакшн-релізу.

---

## 1. Заморожені файли

Ці файли **не редагуються** без явної письмової вказівки, яка називає файл поіменно:

```
src/components/Header.astro
src/components/Footer.astro
src/layouts/Layout.astro
src/design/tokens.ts
src/design/icons.ts
tailwind.config.mjs
nginx.conf
Dockerfile
```

«Явна вказівка» — це «зміни Footer.astro: …».
Це **не** явна вказівка: «онови контакти», «поправ стилі», «зроби гарніше», «приведи до макета».

Якщо задача виглядає так, ніби потребує зміни замороженого файлу — **зупинись і запитай**, назвавши файл і конкретний рядок.

CI має snapshot-хеші зібраної розмітки `<header>` і `<footer>`. Тиха зміна впаде на перевірці.

---

## 2. Заборонено без прямого запиту

Не роби нічого з цього, навіть якщо здається, що це покращення:

| Заборонено | Чому |
|---|---|
| Змінювати, замінювати або «уніфікувати» іконки | Іконки затверджені дизайном. Беруться тільки з `src/design/icons.ts` |
| Змінювати розмітку або вміст футера / хедера | Затверджено з Figma 1:1 |
| Змінювати кольори, тіні, радіуси, шрифти | Тільки з `src/design/tokens.ts` |
| Змінювати тексти, які тебе не просили змінювати | Тексти вичитані вручну |
| Перейменовувати або переміщувати файли | Ламає імпорти й історію git |
| Додавати залежності в `package.json` | Кожна залежність — це ризик і вага бандла |
| «Оновлювати» версії пакетів | Окрема задача з окремим тестуванням |
| Змінювати `astro.config.mjs`, `tsconfig.json` | Конфігурація збірки |
| Форматувати файли цілком | Форматування ховає реальний диф |
| Додавати анімації, hover-ефекти, градієнти | Не було в макеті |
| Створювати README, CHANGELOG, документацію | Якщо не просили |
| Видаляти код, який здається невикористаним | Спочатку доведи, що він невикористаний, і запитай |

## 3. Джерела правди

Дані **завжди** беруться звідси. Дублювати їх у розмітку сторінок заборонено.

| Що | Файл | Правило |
|---|---|---|
| Кейси (усі 6) | `src/data/cases.ts` | Єдине джерело. `/cases/`, `/cases/[slug]/`, `/catalog/`, карусель на головній — усі читають звідси |
| Навігація, компанія, контакти, соцмережі | `src/data/siteConfig.ts` | Хедер, футер, сторінка контактів, політика — усі звідси |
| Кольори, тіні, радіуси, типографіка | `src/design/tokens.ts` → `tailwind.config.mjs` | Жодного hex у `.astro` |
| Іконки | `src/design/icons.ts` → `<Icon name="…" />` | Жодного інлайнового `<svg>` у сторінках |
| UI-рядки (кнопки, підписи, помилки) | `src/i18n/ui.ts` | Жодного зашитого тексту в розмітці |

**Якщо для задачі потрібне поле, якого немає в моделі даних — додай поле в модель**, а не хардкодь значення в розмітку. Якщо додавання поля здається надмірним — запитай.

## 4. Кольори

Заборонено писати hex у `.astro` і `.ts`-файлах сторінок і компонентів. Заборонено використовувати довільні Tailwind-кольори (`text-purple-200`, `border-sky-400`, `bg-emerald-500` тощо).

```astro
<!-- ❌ ніколи -->
<div class="bg-[#181818] text-[#515151] border-sky-400">
<div style="color: #A10000">

<!-- ✅ завжди -->
<div class="bg-text-main text-text-muted border-brand-red">
```

Потрібен колір, якого немає в палітрі? **Запитай.** Не додавай його самостійно ні в `tokens.ts`, ні інлайном.

CI-скрипт `scripts/check-design-system.mjs` падає на будь-якому hex у `src/**/*.astro`.

---

## 5. Tailwind — тільки v3.4

У проєкті **Tailwind CSS 3.4**. Класи з Tailwind v4 не існують і мовчки ігноруються — помилки не буде, стиль просто не застосується.

Заборонені (вже знайдені в коді, підлягають виправленню):

```
shadow-xs      → shadow-sm
shadow-2xs     → shadow-sm
py-4.5         → py-4 або py-5
size-*         → w-* h-*
```

Перед тим як написати клас, якого раніше не було в проєкті — **перевір, що він існує у v3.4**. Не покладайся на пам'ять: v4 вийшов після навчання більшості моделей, і класи з нього виглядають правдоподібно.

Класи з довільними значеннями (`p-[13px]`, `text-[17px]`) заборонені без узгодження — вони означають, що щось не так зі шкалою.

## 6. Іконки

Усі іконки — з `src/design/icons.ts` через компонент `<Icon />`:

```astro
<!-- ✅ -->
<Icon name="mail" class="w-5 h-5" />

<!-- ❌ інлайновий SVG -->
<svg viewBox="0 0 24 24"><path d="M3 8l7.89 5.26…"/></svg>

<!-- ❌ емодзі та символи як іконки -->
<div>🎯</div>  <div>❖</div>  <div>☩</div>  <div>📊</div>
```

Потрібна іконка, якої немає в реєстрі? **Запитай.** Не малюй свій `<path>`, не бери «схожу» з пам'яті, не став емодзі.

Причина: емодзі рендеряться різними шрифтами на різних ОС, не приймають `stroke-width` і не мають стабільного оптичного розміру. Самописні `<path>` не збігаються з набором за товщиною ліній і сіткою.

## 7. Тексти

- Українські тексти вичитані вручну. **Не «покращуй» формулювання** без запиту.
- Бренд пишеться **точно** так: `AI Hub` — велика латинська **I**, не мала **l**, не кирилична **І**.
- Компанія: `IT SmartFlex` (без дефіса, з пробілом, обидва слова з великої).
- Тире у реченнях — довге «—», не дефіс «-».
- Апостроф — «'» (U+2019), послідовно.
- Нові тексти українською — тільки в `src/i18n/ui.ts` або у відповідному файлі даних, ніколи не в розмітці.

## 8. Обов'язкові перевірки перед завершенням

Виконай **усі** й покажи вивід. Задача не завершена, поки будь-яка з них червона.

```bash
npx astro check        # має бути рівно 0 errors
npm run build          # має завершитись без warnings
node scripts/check-design-system.mjs
node scripts/check-layout-snapshots.mjs
git diff --stat        # подивись на список файлів
```

**Особливо:** подивись на `git diff --stat` і чесно спитай себе — чи всі ці файли справді мали змінитися для цієї задачі?

Якщо у дифі є файл, зміну якого ти не можеш пояснити одним реченням із прив'язкою до формулювання задачі — **відкоти цей файл**.

## 9. Робочий процес

```
гілка від dev → PR → перевірки CI зелені → людина рев'ює → merge у dev
→ деплой на DEV → перевірка людиною → окрема команда людини → PROD
```

- **Ніколи** не пушити напряму в `main`/`prod`.
- **Ніколи** не деплоїти на PROD самостійно. PROD — тільки за окремою явною командою людини, після підтвердження DEV.
- Одна задача = одна гілка = один PR. Не змішуй виправлення багу з рефакторингом.
- Коміти за Conventional Commits: `fix(cases): …`, `feat(i18n): …`.

---

## 10. Формат підсумку

Кожну задачу завершуй так:

```markdown
## Зроблено
- <зміна> — <файл:рядок> — <навіщо, з прив'язкою до задачі>

## Файли змінено
<вивід git diff --stat>

## Перевірки
- astro check: 0 errors
- build: OK
- check-design-system: OK
- check-layout-snapshots: OK

## Помічено, але НЕ змінено
- <проблема> — <файл:рядок> — <чому не чіпав>

## Потребує рішення людини
- <питання>
```

Розділ «Помічено, але НЕ змінено» — обов'язковий і не може бути порожнім без пояснення. Він існує саме для того, щоб ти міг зафіксувати знайдені проблеми, не змінюючи їх.

## 11. Коли зупинитися і запитати

Зупинись, якщо:

- задача потребує зміни файлу зі списку §1;
- потрібен колір, іконка або шрифт, яких немає в реєстрах;
- інструкція суперечить цьому файлу;
- задача сформульована як «зроби краще» / «приведи до макета» / «поправ стилі» без конкретики;
- виправлення потребує зміни форми даних (інтерфейсу) в `src/data/`;
- диф перевищує ~15 файлів;
- щось не працює, і найпростіше рішення — переписати компонент цілком.

Запитати — це нормально й очікувано. Мовчки зробити на свій розсуд — ні.

## 12. Контекст проєкту

- **Стек:** Astro 4.16 (SSG, `output: 'static'`), TypeScript strict, Tailwind CSS 3.4, Docker (node:20-alpine → nginx:alpine), Google Cloud Run.
- **Мови:** `uk` — дефолт на `/`. `en` — на `/en/` через нативний Astro i18n (див. `EN_I18N_PLAN.md`).
- **Аналітика:** Google Analytics 4 (Consent Mode v2) + Amplitude (`serverZone: 'EU'`).
  **Жодних персональних даних в аналітику.** Ніколи не додавай email, телефон, ПІБ, вміст форм у властивості подій.
- **Середовища:** DEV (`gen-lang-client-0138386785`) → PROD (`ai-hub-504115`).
- `astro build` **не перевіряє типи.** Зелена збірка нічого не гарантує. Джерело правди щодо коректності — `astro check`.

## 13. Відомі пастки цього репозиторію

Прочитай перед першою задачею:

1. **`astro build` завжди зелений**, навіть коли сторінка рендерить `[object Object]`. Довіряй тільки `astro check`.
2. **Tailwind мовчки ігнорує неіснуючі класи.** `shadow-xs` не дасть помилки — просто не буде тіні.
3. **`cases.ts` має структуру `{uk, en}`** для текстових полів. `item.title` — це об'єкт, не рядок. Треба `item.title.uk`.
4. **Контент історично дублювався** в `catalog.astro` і `index.astro`. Після консолідації — тільки `cases.ts`.
5. **`solutions.ts` і `contacts.ts` були мертвим кодом.** Якщо вони ще є — не додавай туди нічого, спитай.
6. **Шрифт Fixel Text немає в Google Fonts** — він хоститься локально з `public/fonts/`. Не «виправляй» це на посилання до Google Fonts.
7. **`sitemap.xml.ts` і `robots.txt` беруть домен з конфігу**, не з хардкоду. Не вписуй домен вручну.
